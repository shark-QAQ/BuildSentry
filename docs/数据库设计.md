# 工安智审（BuildSentry）
## 数据库设计说明书（DBD）V1.0


## 1. 设计概述

### 1.1 数据库选型

| 组件               | 技术选型       | 理由                                           |
| :----------------- | :------------- | :--------------------------------------------- |
| **关系型数据库**   | PostgreSQL 16+ | 稳定可靠，支持JSONB，生态完善                  |
| **向量扩展**       | pgvector 0.5+  | 原生向量检索，避免引入额外组件，降低运维复杂度 |
| **缓存层（可选）** | Redis          | 用于Session缓存、频繁查询结果缓存              |

### 1.2 设计原则

1. **范式与反范式平衡**：核心业务表遵循3NF，审核结果等查询密集型表适度冗余
2. **JSONB灵活存储**：对动态字段（如审核元数据、模型参数）使用JSONB类型
3. **软删除策略**：关键业务表使用 `deleted_at` 字段，避免物理删除导致审计链路断裂
4. **分区策略**：`audit_tasks` 和 `violations` 表按月份分区，便于归档
5. **向量与标量混合查询**：利用pgvector实现"规范条文检索+关键词过滤"

#### 3.2.3 条文向量表（pgvector核心）

```sql
-- 启用pgvector扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 条文向量索引表（与clauses一对一）
CREATE TABLE clause_embeddings (
    id BIGSERIAL PRIMARY KEY,
    clause_id BIGINT NOT NULL REFERENCES clauses(id) ON DELETE CASCADE,
    embedding vector(1024),                  -- 使用 bge-large 1024维
    model_name VARCHAR(64) DEFAULT 'BAAI/bge-large-zh-v1.5',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(clause_id, model_name)

-- HNSW向量索引（查询速度快，适合百万级以下数据）
CREATE INDEX idx_clause_embeddings_hnsw ON clause_embeddings 
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 200);
```

## 4. 向量检索关键SQL示例

### 4.1 RAG检索：查找与施工方案段落最相关的规范条文

```sql
WITH target_embedding AS (
    SELECT $1::vector AS vec
)
SELECT 
    c.article_id,
    c.content,
    s.spec_code,
    ce.embedding <=> te.vec AS similarity_score
FROM clause_embeddings ce
CROSS JOIN target_embedding te
JOIN clauses c ON c.id = ce.clause_id
JOIN specifications s ON s.id = c.spec_id
WHERE s.status = 1
  AND ce.embedding <=> te.vec < 0.8
ORDER BY ce.embedding <=> te.vec
LIMIT 5;
```

### 4.2 混合检索：关键词 + 向量

```sql
WITH keyword_matches AS (
    SELECT 
        c.id,
        c.article_id,
        c.content,
        s.spec_code,
        ts_rank_cd(to_tsvector('chinese', c.content), plainto_tsquery('chinese', '基坑 支护 放坡')) AS rank
    FROM clauses c
    JOIN specifications s ON s.id = c.spec_id
    WHERE s.status = 1
      AND to_tsvector('chinese', c.content) @@ plainto_tsquery('chinese', '基坑 支护 放坡')
    ORDER BY rank DESC
    LIMIT 20
)
SELECT 
    km.article_id,
    km.content,
    km.spec_code,
    ce.embedding <=> $1::vector AS vector_score,
    km.rank AS bm25_score
FROM keyword_matches km
JOIN clause_embeddings ce ON ce.clause_id = km.id
ORDER BY (ce.embedding <=> $1::vector) * 0.7 + (1.0 / (km.rank + 1)) * 0.3
LIMIT 5;
```


## 5. 数据生命周期管理策略

### 5.1 数据分级与保留策略

| 数据类别     | 表                        | 在线保留 | 归档策略       |
| :----------- | :------------------------ | :------- | :------------- |
| **热数据**   | violations, audit_results | 6个月    | 迁移至历史库   |
| **温数据**   | audit_tasks, documents    | 12个月   | 迁移至历史库   |
| **冷数据**   | operation_logs            | 3个月    | 迁移至对象存储 |
| **元数据**   | specifications, clauses   | 永久     | 不归档         |
| **向量数据** | clause_embeddings         | 永久     | 不归档         |

### 5.2 分区表实现（按月分区）

```sql
-- 以 audit_tasks 为例
CREATE TABLE audit_tasks_partitioned (
    LIKE audit_tasks INCLUDING ALL,
    created_at TIMESTAMP NOT NULL
) PARTITION BY RANGE (created_at);

CREATE TABLE audit_tasks_2026_01 PARTITION OF audit_tasks_partitioned
    FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');
```
