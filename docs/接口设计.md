# 工安智审（BuildSentry）
## API接口设计说明书 V1.0


## 1. 接口设计原则

| 原则             | 说明                                                   |
| :--------------- | :----------------------------------------------------- |
| **RESTful风格**  | 遵循标准HTTP方法（GET/POST/PUT/DELETE），资源化URL设计 |
| **统一响应格式** | 所有接口返回统一的JSON结构，包含状态码、消息和数据     |
| **异步任务模式** | 审核操作耗时较长，采用“提交→轮询→获取结果”的异步模式   |
| **版本控制**     | URL路径包含版本号（如 `/api/v1/`），便于后续平滑升级   |
| **错误码体系**   | 业务错误码与HTTP状态码分离，提供明确的错误语义         |


## 2. 接口总览

| 模块         | 方法   | 路径                                       | 功能           | 说明                     |
| :----------- | :----- | :----------------------------------------- | :------------- | :----------------------- |
| **认证授权** | POST   | `/api/v1/auth/register`                    | 用户注册       | 固定创建 viewer          |

|              | GET    | `/api/v1/system/metrics`                   | 获取监控指标   | 返回吞吐量、延迟等       |

### 3.4 错误码表

| 错误码 | HTTP状态码 | 含义                     | 处理建议           |
| :----- | :--------- | :----------------------- | :----------------- |
| 200    | 200        | 请求成功                 | -                  |
| 40001  | 400        | 不支持的文档格式         | 检查文件后缀名     |
| 40002  | 400        | 文档内容为空             | 重新上传有效文件   |
| 40003  | 400        | 文档体积超限（上限50MB） | 压缩或拆分文件     |
| 40004  | 400        | 违规参数校验失败         | 检查请求体字段     |
| 40101  | 401        | 未登录或Token过期        | 重新登录           |
| 40301  | 403        | 无操作权限               | 联系管理员开通权限 |
| 40401  | 404        | 文档不存在               | 检查文档ID         |
| 40402  | 404        | 任务不存在               | 检查任务ID         |
| 40403  | 404        | 规范不存在               | 检查规范ID         |
| 40901  | 409        | 文档已在审核中           | 等待当前审核完成   |
| 42901  | 429        | 请求过于频繁             | 降低请求频率       |
| 50001  | 500        | 审核引擎异常             | 稍后重试或联系运维 |
| 50002  | 500        | 模型加载失败             | 检查模型文件完整性 |


## 4. 核心接口详细定义

### 4.1 上传施工方案

**接口描述**：上传施工方案文档，系统自动提取文本并解析章节结构。

**请求**

| 属性         | 说明                                            |
| :----------- | :---------------------------------------------- |
| 方法         | POST                                            |
| 路径         | `/api/v1/documents/upload`                      |
| 认证         | 需要（Header: `Authorization: Bearer {token}`） |
| Content-Type | `multipart/form-data`                           |

**请求参数（Form-Data）**

| 参数名       | 类型   | 必填 | 说明                                 |
| :----------- | :----- | :--- | :----------------------------------- |
| file         | File   | 是   | 施工方案文件（.pdf/.docx），最大50MB |
| title        | String | 否   | 方案标题，为空则从文件中提取         |
| project_name | String | 否   | 关联的项目名称                       |
| company      | String | 否   | 提交单位名称                         |

**响应示例**

```json
{
    "code": 200,
    "message": "上传成功",
    "data": {
        "doc_id": 10001,
        "file_name": "深基坑专项施工方案_v3.pdf",
        "file_size": 2457600,
        "status": "parsing",
        "created_at": "2026-09-08T14:30:00Z"
    }
}
```

**业务逻辑说明**：
1. 文件上传后立即计算SHA256哈希值，与已有文档对比。若哈希相同且已解析成功，直接返回已存在的文档ID，避免重复存储。
2. 异步启动文档解析任务（调用解析服务），状态从 `pending` → `parsing` → `parsed` / `failed`。
3. 解析内容包括：纯文本提取、章节结构识别、字数统计。

### 4.3 创建审核任务（核心接口）

**接口描述**：对已上传的施工方案启动合规审核。系统根据 `doc_id` 获取文档内容，按段落切分后并行审核，最终聚合生成审核报告。

**请求**

| 属性 | 说明                  |
| :--- | :-------------------- |
| 方法 | POST                  |
| 路径 | `/api/v1/audit/tasks` |
| 认证 | 需要                  |

**请求体（JSON）**

| 字段               | 类型    | 必填 | 说明                         |
| :----------------- | :------ | :--- | :--------------------------- |
| doc_id             | Integer | 是   | 文档ID，必须为 `parsed` 状态 |
| config             | Object  | 否   | 覆盖默认审核参数             |
| config.temperature | Number  | 否   | 模型温度（0.0~1.0），默认0.1 |
| config.top_k       | Integer | 否   | RAG检索条数（3~10），默认5   |
| config.max_tokens  | Integer | 否   | 输出最大token数，默认2048    |
| priority           | Integer | 否   | 优先级（1~10），默认5        |
| callback_url       | String  | 否   | 审核完成后的回调通知地址     |

**请求示例**

```json
{
    "doc_id": 10001,
    "config": {
        "temperature": 0.05,
        "top_k": 7
    },
    "priority": 3,
    "callback_url": "https://webhook.example.com/audit-callback"
}
```

**响应示例**

```json
{
    "code": 200,
    "message": "审核任务已创建",
    "data": {
        "task_id": 50001,
        "task_no": "AT-20260908-001",
        "status": "queued",
        "estimated_time": 25,
        "queued_at": "2026-09-08T14:30:00Z"
    }
}
```

**业务逻辑说明**：
1. 校验 `doc_id` 状态必须为 `parsed`，否则返回 40001。
2. 同一份文档如果有 `running` 状态的任务，返回 40901 冲突。
3. 系统从 `system_configs` 读取默认参数，被请求体 `config` 覆盖后，连同当前激活的模型版本一并存入 `config_snapshot` 字段。
4. 任务入队后立即返回 `task_id`，实际审核在后台异步执行。

### 4.6 下载PDF审核报告

**接口描述**：下载带公章的PDF格式审核报告，适合打印归档或发送给施工方。

**请求**

| 属性 | 说明                                   |
| :--- | :------------------------------------- |
| 方法 | GET                                    |
| 路径 | `/api/v1/audit/tasks/{task_id}/report` |
| 认证 | 需要                                   |
| 响应 | 文件流（application/pdf）              |

**响应头示例**

```
Content-Type: application/pdf
Content-Disposition: attachment; filename="审核报告_AT-20260908-001.pdf"

```

**业务逻辑说明**：
1. 若报告尚未生成（任务未完成），返回 40402 并提示 "报告生成中，请稍后重试"。

### 4.7 人工复核违规项

**接口描述**：审核员确认、驳回或修正AI发现的违规项，反馈数据用于模型迭代。

**请求**

| 属性 | 说明                                      |
| :--- | :---------------------------------------- |
| 方法 | PUT                                       |
| 路径 | `/api/v1/audit/violations/{violation_id}` |
| 认证 | 需要（角色：auditor 或 admin）            |

**请求体（JSON）**

| 字段                | 类型   | 必填 | 说明                            |
| :------------------ | :----- | :--- | :------------------------------ |
| action              | String | 是   | `confirm` / `reject` / `revise` |
| revised_clause_code | String | 否   | action=revise 时必填            |
| revised_description | String | 否   | action=revise 时必填            |
| revised_suggestion  | String | 否   | action=revise 时必填            |
| comment             | String | 否   | 复核备注                        |

**请求示例**

```json
{
    "action": "revise",
    "revised_clause_code": "JGJ 59-2011 第3.11.4条",
    "revised_description": "基坑周边堆载距坑边不足3米，违反强制性条文3.11.4。",
    "revised_suggestion": "立即移除，材料堆放距坑边不得小于5米。",
    "comment": "原违规描述准确，但条款编号引用有误，已修正。"
}
```

**响应示例**

```json
{
    "code": 200,
    "message": "复核成功",
    "data": {
        "violation_id": 20001,
        "human_review_status": "revised",
        "human_review_by": "张三",
        "human_review_at": "2026-09-08T16:00:00Z"
    }
}
```

**业务逻辑说明**：
1. `confirm`：确认AI判定正确，`human_review_status` 置为 `confirmed`。
2. `reject`：判定为误报，`human_review_status` 置为 `rejected`。
3. `revise`：修正内容，`human_review_status` 置为 `revised`。同时异步向 `audit_feedbacks` 表写入一条反馈记录，供后续训练数据准备使用。
4. 只有 `pending` 状态的违规项可复核，已复核的不可重复操作。

### 4.8 规范条文检索

**接口描述**：通过关键词或自然语言查询规范条文，用于知识库检索和方案编写时的参考查阅。

**请求**

| 属性 | 说明                 |
| :--- | :------------------- |
| 方法 | GET                  |
| 路径 | `/api/v1/kb/clauses` |
| 认证 | 需要                 |

**请求参数（Query String）**

| 参数名       | 类型    | 必填 | 说明                                   |
| :----------- | :------ | :--- | :------------------------------------- |
| q            | String  | 是   | 查询关键词或自然语言，如"基坑放坡系数" |

### 4.9 上传规范文档（管理员接口）

**接口描述**：管理员上传新的施工规范PDF，系统自动解析条文并入库，同时生成向量索引。

**请求**

| 属性         | 说明                  |
| :----------- | :-------------------- |
| 方法         | POST                  |
| 路径         | `/api/v1/kb/specs`    |
| 认证         | 需要（角色：admin）   |
| Content-Type | `multipart/form-data` |

**请求参数（Form-Data）**

| 参数名       | 类型    | 必填 | 说明                                      |
| :----------- | :------ | :--- | :---------------------------------------- |
| file         | File    | 是   | 规范PDF文件                               |
| spec_code    | String  | 是   | 规范编号，如 `JGJ 59-2011`。空值返回 40002 |
| spec_name    | String  | 是   | 规范全称。空值返回 40002                   |
| is_mandatory | Boolean | 否   | 是否强制性标准，默认false                 |
| category     | String  | 否   | 分类：房建/市政/公路/水利                 |

>
> 规范 PDF 版式差异较大，建议先带 `dry_run=true` 调一次，确认条文切分质量

```json
{

        "spec_name": "建筑施工安全检查标准",
        "parse_status": "parsing",
        "estimated_clauses": 180
    }
}
```

**业务逻辑说明**：
1. 校验PDF文件格式，解析失败时返回 40001 并给出详细错误信息。
2. 解析完成后向 `spec_upload_logs` 表写入日志，记录解析耗时和解析出的条文数量。
3. 解析成功的条文自动向量化，存入 `clause_embeddings` 表。

## 6. 认证与授权

### 6.1 认证方式

采用 **Bearer Token（JWT）** 认证方式。

**请求头示例**：
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 6.2 权限角色

| 角色          | 权限范围                               |
| :------------ | :------------------------------------- |
| **viewer**    | 查看文档、查看审核结果                 |
| **submitter** | viewer + 上传文档、提交审核            |
| **auditor**   | submitter + 人工复核违规项             |
| **admin**     | auditor + 上传规范、切换模型、系统配置 |

### 6.3 接口一览

| 方法   | 路径                           | 认证          | 说明               |
| :----- | :----------------------------- | :------------ | :----------------- |
| POST   | `/api/v1/auth/register`        | 不需要        | 自助注册，固定 viewer |
| POST   | `/api/v1/auth/login`           | 不需要        | 登录换取 Token     |
| GET    | `/api/v1/auth/me`              | 需要          | 获取当前用户信息   |
| PUT    | `/api/v1/auth/me/password`     | 需要          | 修改自己的密码     |
| GET    | `/api/v1/auth/users`           | 需要（admin） | 用户列表           |
| POST   | `/api/v1/auth/users`           | 需要（admin） | 创建用户并指定角色 |
| DELETE | `/api/v1/auth/users/{user_id}` | 需要（admin） | 删除用户           |

> **响应格式不同于第 3 章**：本章接口返回的是**裸模型**，不带
> `{code, message, data, timestamp}` 信封。各接口示例即为实际响应。

### 6.4 注册

| 属性 | 说明                    |
| :--- | :---------------------- |
| 方法 | POST                    |
| 路径 | `/api/v1/auth/register` |
| 认证 | 不需要                  |

**请求体**
```json
{
    "username": "zhangsan",
    "email": "zhangsan@example.com",
    "password": "Passw0rd!",
    "full_name": "张三"
}
```

**响应 `200`**
```json
{
    "id": 2,
    "username": "zhangsan",
    "email": "zhangsan@example.com",
    "full_name": "张三",
    "role": "viewer",
    "is_active": true,
    "created_at": "2026-09-14T11:37:05",
    "last_login": null
}
```

`role` **不是可传字段**：注册一律创建 `viewer`。请求体带 `role` 会因多余字段被判
`422` —— 刻意不静默忽略，否则调用方会误以为提权成功。特权角色只能由管理员经
`POST /api/v1/auth/users` 创建。

| :--- | :------------------- |
| 方法 | POST                 |
| 路径 | `/api/v1/auth/login` |
| 认证 | 不需要               |

**请求体**
```json
{
    "username": "admin",
    "password": "Admin@2026"
}
```

**响应 `200`**
```json
{
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
```

### 6.7 用户管理（仅管理员）

**获取用户列表**

| 属性 | 说明                                             |
| :--- | :----------------------------------------------- |
| 方法 | GET                                              |
| 路径 | `/api/v1/auth/users`                             |
| 认证 | 需要（角色：admin）                              |
| 参数 | `skip`（默认 0）、`limit`（默认 100），均为查询串 |

响应为 6.4 中用户对象的数组。

**创建用户**

| 属性 | 说明                 |
| :--- | :------------------- |
| 方法 | POST                 |
| 路径 | `/api/v1/auth/users` |
| 认证 | 需要（角色：admin）  |

**请求体**
```json
{
    "username": "auditor01",
    "email": "auditor01@example.com",
    "password": "Auditor@2026",
    "full_name": "张审核",
    "role": "auditor"
}
```

`role` 仅接受 `viewer` / `submitter` / `auditor` / `admin`，其它取值 → `422`。
成功返回 `201` 与创建出的用户。非管理员调用 → `403`。

**删除用户**

| 属性 | 说明                           |
| :--- | :----------------------------- |
| 方法 | DELETE                         |
| 路径 | `/api/v1/auth/users/{user_id}` |
| 认证 | 需要（角色：admin）            |

**响应 `200`**
```json
{
    "message": "用户删除成功"
}
```

删除自己 → `400` / `40006`；用户不存在 → `404` / `40403`。

### 6.8 认证相关错误码

| 错误码 | HTTP | 含义                |
| :----- | :--- | :------------------ |
| 40002  | 400  | 用户名已存在        |
| 40003  | 400  | 邮箱已被注册        |
| 40005  | 400  | 旧密码错误          |
| 40006  | 400  | 不能删除自己        |
| 40101  | 401  | 未登录或 Token 失效 |
| 40102  | 401  | 用户名或密码错误    |
| 40301  | 403  | 权限不足            |
| 40302  | 403  | 账户已被禁用        |
| 40403  | 404  | 用户不存在          |
| 422    | 422  | 请求体字段校验失败  |

> **注意：错误码在不同模块间存在重号。** 上表中的 `40002` 在 3.4 节被定义为
> 「文档内容为空」、在知识库模块又表示「`spec_code`/`spec_name` 为空」；
> `40003`、`40004`、`40403` 同样一码多义。客户端**不能**只凭 `code` 判断错误类型，
> 需结合请求路径。这是当前实现的已知不一致，尚未统一。


## 7. 限流策略

| 接口类型   | 限流规则       | 说明                 |
| :--------- | :------------- | :------------------- |
| 文档上传   | 10次/分钟/用户 | 防止恶意超大文件上传 |
| 创建审核   | 5次/分钟/用户  | 控制算力消耗         |
| 查询接口   | 60次/分钟/用户 | 正常轮询频率         |
| 管理员接口 | 20次/分钟/用户 | 配置类操作低频       |

**限流响应示例**（HTTP 429）：
```json
{
    "code": 42901,
    "message": "请求过于频繁，请稍后重试",
    "retry_after": 30,
    "timestamp": "2026-09-08T14:30:00Z"
}
```
