# BuildSentry（工安智审）

**把一份几十页的工程合规资料交给 32B 模型逐条审——目标是「零编造」。**

不是"让模型更会答"，而是**在设计上让它没有机会编造**。

`Qwen3-32B` · `QLoRA (4bit nf4)` · `vLLM + LoRA` · `RAG (ChromaDB)` · `FastAPI` · `Gradio`

> 📹 演示 GIF / 截图：待补
>
> 状态：V1.0，合成评测集验证完毕，尚未接入真实审计验收。

---

## 30 秒：这个场景真正难的地方

合规审核的失败**不是"答错了"，是"答得很像对的"**。

模型报出一条"违反《XX 规范》第 5.3.2 条"，条号存在、措辞专业、格式完美——但这部规范里根本没有这一条。

审核员一旦信了，后果比"我不知道"严重得多。

所以这个项目的核心命题是：

> **怎么让模型在"不知道"的时候，说不知道；而不是补一个看起来合理的条款号。**

答案不是调 prompt，是**在数据管线和推理链路上，把"编造"这件事的物理条件去掉**。

---

## 核心设计：数字不由模型生成

这是整个项目最关键的一个决定。

**常规做法**：让 LLM 直接生成一份合规资料草稿（含各种参数、工序、材料指标），再拿去训练审核模型。
**问题**：模型得先记住 1212 条规则里的数字，只要记错一个，整份训练数据就是错的——而且错得悄无声息。

**本项目做法**：

```
规则表（1212 条：量化 483 / 禁止性 729）
   ↓  模板确定性渲染，数字直接取自规则表
文档骨架（每个字段都在该字段全部规则约束的区间内取值）
   ↓  LLM 只负责把模板腔润色成公文腔
成稿（措辞可以变，数字零容忍）
```

**LLM 的任务从"生成"降级为"改写"——它不需要知道正确数字是什么。**

即便它出错，也只错在措辞，不会错在数值。

同理，合成训练数据时**被测模型不能自己造数据**：本项目用 `Qwen3-30B-A3B` 生成，被测基座是 `Qwen3-32B`——用被测模型生成自己的训练集，等于数据泄漏。

## 数据管线

```
依据库   52 部法规（1983 条） + 54 部标准（5324 条） = 7307 条条文
   ↓
规则表   1212 条（量化 483 / 禁止性 729）
         + 48 条触发规则 + 368 条常见误区 + 22 条隔离名单
   ↓
① 合规基线   每个字段在其全部规则约束出的区间内随机取值
② 受控注入   定向破坏，violation : distractor : negative = 6 : 2 : 2
             注入记录即 ground truth（真实底稿涉密，故把因果反过来）
③ 渲染成文档 模板确定性渲染，数字取自规则表
④ LLM 改写   只改措辞，数字零容忍
⑤ 五道质检   训练 12000 / 评测 1500，跨任务 MD5 交集 = 0
```

四个训练任务：

| 任务 | 内容 | 训练 | 评测 |
| --- | --- | ---: | ---: |
| A | 单项合规判定（三态：合规 / 不合规 / 依据不足） | 5000 | 600 |
| B | 全量违规检出（整份资料包 → 违规清单 JSON） | 3000 | 500 |
| C | 法条问答 | 2000 | 200 |
| D | 多轮追问 | 2000 | 200 |

## 一次差点毁掉整个评测的事故

v2 训完之后，指标很漂亮：**违规检出召回 91.9%，精确率 98.7%，高风险漏判 0**。

但做数据体检时发现：**39.7% 的评测参考答案，在给定资料里根本不可见。**

也就是说，模型被要求"找出资料里的违规"，而参考答案里的那些违规，资料里压根没写。
模型只有两条路：漏掉（算它错），或者编出来（算它对）。

**「召回 91.9%」这个数字是缺陷的产物**——它既低估了模型（可答部分实际是 100.0%），
又高估了它（掺了 1202 个纯靠模板发射、根本不需要读资料的"命中"）。

拆开看：

| 分组 | 参考 | 命中 | 漏 | 误报 | 召回 | 精确 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **可答**（资料里真有） | 3249 | 3248 | **1** | 35 | **100.0%** | **98.9%** |
| 不可答（资料里没有） | 2141 | 90 | 2051 | 0 | 4.2% | — |

> **教训：先验证评测集，再相信指标。** 一个坏掉的评测集，会让好模型看起来平庸，让坏模型看起来优秀。

## 指标自检：先证明尺子是准的

在相信任何数字之前，用两个极端策略跑一遍：

| 策略 | 任务 A 三态 | 任务 B 召回 | 高风险漏判率 |
| --- | ---: | ---: | ---: |
| 全报合规（偷懒） | 34.0% | 0.0% | **100%** ← 正确惩罚 |
| 照抄参考（满分） | 100% | 100% | 0.0% ← 正确奖励 |

**偷懒策略如果拿到好看的分，说明指标或评测集坏了。**

这一步花十分钟，但它是后面所有结论的前提。

---

## 清洗数据后：v2 vs v3 的公平对照

把 40% 的假参考答案清掉，重训 v3。同一份干净参考答案上对比：

| | tp | fp | fn | 召回 | 精确 | 高风险漏判 | **接地图需剔除** |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| v2 | 2971 | 32 | 1 | 100.0% | 98.9% | 0.00% | **1251 条** |
| **v3** | 2972 | **6** | **0** | 100.0% | **99.8%** | 0.00% | **0 条** |

**这两行必须连起来读。**

单看指标，两代差距不大。但 v2 每次要吐出 **1251 条编造内容**，全靠接地图（guardrail）删掉，才能得到上面那行数字。

> **护栏是安全网，不是拐杖。** v2 拔掉护栏就不能用，v3 不需要护栏也能用。

还有一组行为探针（task_b 前 30 条）：

| 探针 | v2 | v3 |
| --- | --- | --- |
| 报出资料中不可见字段的样本 | **30/30 = 100%** | **0/30 = 0%** |
| 条款组合多样性 | 500 条里只有 5 种组合 | 30 条有 14 种，最大签名簇仅 1 条 |
| 报零违规 vs 参考答案为空 | — | **16/30 vs 16/30，完全吻合** |

最后一行的意义：清洗后 39.7% 的样本参考答案为空，曾担心模型变得过度保守、什么都不敢报。
实测报 16 空 / 14 非空，参考答案正好也是 16 / 14。

**模型没有变保守，它只是终于学会了「没有就是没有」。**

## 训练与部署

| 项 | 内容 |
| --- | --- |
| 基座 | Qwen3-32B（本地，不调外部 API） |
| 微调 | QLoRA：4bit nf4 + 双量化，`r=16 / alpha=32 / dropout=0.05`，全 7 个投影层 |
| 训练 | 3 epoch / 1071 步 / `max_seq_len=8192` / 4×RTX A6000 48G，**8h42m** |
| 适配器 | 537MB |
| 部署 | **bf16 基座 + 运行时挂 LoRA**，vLLM `--enable-lora`，TP=2 |
| 护栏 | `guardrail.py`（规则引擎 + 模型的合流点） |

**刻意不合并、不量化。** 两条路上都实测丢了微调行为——模型还是那个模型，但"守规矩"的能力没了。

> `max_seq_len=8192` 不是调优，是必须：任务 B 的违规清单约 3500 字，默认 1024 会静默截断。

## 压测（TP=2，bf16 + LoRA）

混合负载 60 条（短问 40 / 长资料 20），0 错误，`max_tokens=3072`、`temperature=0`：

| 并发 | 请求/秒 | 输出 tok/秒 | P50 | P95 | P99 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.05 | 16.3 | 6.3s | 118s | 167s |
| 4 | 0.17 | 53.9 | 6.2s | 114s | 161s |
| 12 | 0.33 | 107.3 | 6.4s | 117s | 164s |
| 24 | 0.35 | 112.7 | 7.0s | 119s | 167s |

- **拐点在并发 12**：12→24 吞吐只涨 5%，再往上只堆延迟。生产建议跑 12
- P50 稳定在 6–7s，几乎不随并发劣化
- P95 约 118s 是部分请求写满 `max_tokens` 所致，不是排队（`Waiting: 0` 全程成立）

### 一个容易被误读的数字

v3 的 `输出 tok/秒` 比 v2 **低 16%**（134.7 → 112.7）。

**这不是变慢，是它少吐了垃圾**：

| | 平均输出长度 | 平均报出违规数 |
| --- | ---: | ---: |
| v2 | 2224 字 | 8.97 条 |
| v3 | **1657 字** | **6.49 条** |

差的 2.48 条，正好等于 v2 平均每条编造的数量（实测 2.49）。

而真实指标全部变好：请求/秒 0.32 → **0.35**，P50 8.6s → **7.0s**，整轮墙钟 188s → **171s**。

> **吞吐类指标必须与输出长度一起看。** 单看 tok/秒，会把"少说废话"误判成"性能退化"。

## 能力边界（必须声明）

- **以上是合成评测集上的结果，不是真实审计验收。** 受控注入保证了 ground truth 准确，但合成分布与真实底稿仍有差距。
- 审计检查点主体是**程序性合规**（招投标 / 合同 / 施工程序），这是审计实务的真实分布；施工技术指标判定不在范围内。
- **幻觉无法绝对归零。** 模型尽力 + 护栏兜底，这是设计前提，不是缺陷。
- 真实底稿涉密，训练数据全部为合成；接入真实场景需重新校准。

## 快速开始

```bash
uv sync
cp .env.example .env

# 无 GPU 也能跑通链路（自动降级为模拟审核，返回格式与真实模式一致）
python start.py
```

- API 文档：http://localhost:8000/docs
- 前端界面：http://localhost:7860

### 关于"降级"

`LORA_PATH` 填了但路径不存在时，系统**回退模拟模式并记 ERROR 日志**，而不是悄悄改用基座模型。

> 因为悄悄降级的后果是：报告里看不出微调其实没生效。**失败必须显式。**

## 配置

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `BASE_MODEL` | `Qwen/Qwen3-8B` | 演示配置（默认）；完整实验用 `Qwen3-32B`，见 `docs/训练报告与踩坑记录.md` |

| `CHROMA_COLLECTION_NAME` | `clauses` | 向量集合 |
| `EMBEDDING_MODEL` | `BAAI/bge-small-zh-v1.5` | 换模型会变维度，须重建集合并重灌 |
| `SEED_DEMO_DATA` | `true` | 生产一律不插入 |
| `SIMULATION_DELAY` | `0.5` | 模拟推理延迟（秒） |
